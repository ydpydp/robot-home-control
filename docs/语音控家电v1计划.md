# 语音控家电 v1 计划（蓝牙直连）

- 日期：2026-10-31
- 目标（一句话）：“小箭小箭，帮我打开客厅灯”能跑通——语音 → 服务器 → 蓝牙 → 灯亮 → 语音确认。
- 配套文档：`智能家居常用词汇表.md`（意图词库）

## 一、已定事项（v1 冻结）

1. 拓扑：语音助手（N16R8，ESP32-S3）直接蓝牙控制执行设备；无控制网关、无服务器 MQTT、无 4G。
2. 执行设备：ESP32-S3 N8R8 + 继电器；ESP01 出局（无蓝牙）。
3. 语音助手：N16R8 不变，唤醒词“小箭小箭”，WiFi 连 ECS 服务器。
4. 意图：槽位组合匹配 + 分层决策（全命中执行 / 近命中追问一句 / 没命中走闲聊）；不用整句精确匹配。
5. 确认语义：执行设备回执到了才说确认句；超时说失败句；绝不说假话、绝不沉默。
6. 服务器：后端保持 stdlib-only；不装 Mosquitto。
7. 暂缓（不在 v1）：4G 直连（以后远设备可再用）、控制网关 / 局域 MQTT、BLE Mesh、多房间路由、手机 App / 定时控制、门锁 / 燃气 / 热水器等安全类设备。

## 二、链路（端到端）

语音助手录音 → POST /voice → ECS 后端（ASR → 槽位匹配 → 控制分支）→ 响应里带 X-Command 命令头 + 确认音首段 → 语音助手 BLE 写命令 → N8R8 驱动继电器 → N8R8 经 notify 回状态 → 语音助手按回执选播确认音 / 失败音。

- 确认音 = 正常语音回复的各段；失败音经新增 /speak 接口取（语音助手本地合成不了语音）。
- 确认音的段预取与 BLE 执行并行，延迟藏得住。

## 三、协议草案（v1 建议，动手前冻结）

### 3.1 服务器 → 语音助手：X-Command 响应头

- 格式（v1）：`设备:动作[:参数]`，如 `livingroom_light:on`、`livingroom_light:off`；以后扩展为 JSON。
- 失败文案由服务器定：X-Failure-Text 头，如“客厅灯没有回应”，语音助手原样传给 /speak。
- 无命令的闲聊回复不带 X-Command，语音助手按原流程播回答。

### 3.2 语音助手 → N8R8：BLE GATT

- 语音助手 = central，N8R8 = peripheral；连接保持常连（按需建连每次多 1-3 秒，不用）。
- 服务：自定义服务 UUID（写代码时分配）；两个 characteristic：命令（write，如 ON / OFF / BRI:80）、状态（notify，如 ON / OFF / BRI:80）。v1 用可读文本，调试方便；命令幂等，重发安全。
- 绑定：v1 单灯，语音助手扫描到广播该服务 UUID 的设备自动连接绑定；多设备以后加配对模式 + 语音绑定。
- 安全：LE Secure Connections 绑定，只接受已绑定 central 的连接。
- 回执超时：2 秒（在 3 秒总预算内）；超时走失败音。

## 四、改动清单

### 后端（ECS /opt/robot/robot_backend.py）

- 意图命中后走控制分支（槽位 → 设备 / 动作 / 参数）。
- /voice 响应加 X-Command、X-Failure-Text 头。
- 新增 /speak 接口：GET，text 参数，复用 Kokoro + 分段格式，返回失败音各段。
- 不动：ASR、LLM、TTS 主链路、Piper 备份、stdlib-only。

### 语音助手固件（robot-home-control 仓库，以老仓 main 20ca9c4a 为种子）

- 新增 BLE central 模块：扫描、绑定、常连、断线重连。
- /voice 响应解析 X-Command；先执行 BLE 命令、等回执，再决定播确认段还是调 /speak 取失败段。
- 不动：唤醒词、VAD、录音、分段播放、预取。

### N8R8 执行设备固件（新写）

- BLE peripheral：GATT 服务、命令写、状态 notify、断线重连、看门狗。
- 继电器 GPIO 驱动；状态变化必回 notify（开 / 关 / 亮度）。
- 板子注意：N8R8 无 USB 串口桥、Type-C CC 悬空，刷机须经 hub / USB-A 转接或 5.1kΩ CC 对地；继电器 GPIO 避开 strapping 引脚（GPIO0/3/45/46）；板载 WS2812（GPIO47）可作配对 / 状态指示。
- 市电部分：先工作台低压试验灯验证，再实装客厅线路。

## 五、交互（v1 建议）

- 两步：说唤醒词 → 听“我在” → 再说命令。语音助手固件零改动。
- 一口气（唤醒词 + 命令连读）需固件加预录音缓冲，列为后续优化，不进 v1。

## 六、测试阶段

1. 离线意图测试：例句集（含 ASR 噪声版）跑槽位匹配器，看命中 / 漏命中率，词库按实测补。
2. 工作台联调：语音助手 + N8R8 + 试验灯（不碰客厅线路），端到端语音实测：开 / 关、回执、超时失败音、断线重连。
3. BLE 距离实测：语音助手摆位 vs 客厅灯位置，确认蓝牙覆盖。
4. 客厅实装 + 端到端语音实测。
5. 回归：原语音问答流程不受影响（闲聊回复无 X-Command，走原流程）。

## 七、不进 v1

- 控制网关、局域 MQTT、服务器 MQTT、4G、BLE Mesh。
- 手机 App、定时 / 场景自动化、多房间路由。
- 调光 / 调色（取决于客厅灯本身能力，现状未知）。
- 门锁 / 燃气 / 热水器等安全类设备；二次确认机制以后再议。
- 断网本地意图兜底（以后再议）。

2. 语音助手摆位与客厅灯的距离（BLE 覆盖）。
3. 两步交互是否接受（一口气优化以后再做）。

5. 本计划文档的修改意见。

## 九、鉴权设计（2026-11-01 定：按此思路走，v1 单用户、多设备预留）

- 设备身份：每设备独立 device_id + 独立 token；语音助手每次请求带 X-Device-Id + X-Device-Token；服务器建设备注册表（device_id → 归属人、状态、额度、绑定的灯），对不上 → 401。
- 响应路由：语音发起的响应沿同一条 HTTP 连接原路返回，不会串；服务器主动发起（以后 App、定时）需设备带身份的长连接（MQTT 按设备 topic、或 WebSocket），v1 不需要。
- 刷机授权：公开代码不含任何凭证（WiFi、token 只在本地 menuconfig，永不进仓库）；无凭证刷机者第一步即被 401 挡住。朋友测试时每人单独发 token（私下渠道），可单独吊销。
- 第二道门：BLE 只接受已绑定的语音助手（LE Secure Connections），陌生设备连不上灯。
- 范围：暂不邀朋友测试，先自己跑通再开放；鉴权按多设备设计、v1 先单用户跑。
